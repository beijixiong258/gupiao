# A 股统一选股分析与三交易日预测

这是一个供个人使用的中国大陆 A 股研究程序。量化分析是默认主流程，预测是需要用户二次确认的高成本可选流程：

1. 分析：可以对一只明确股票复用统一量化方法并回答是否建议买入，也可以从全市场或用户用日常语言描述的范围中选出当前最值得继续研究的股票，并说明量化依据、未满足条件和风险。
2. 预测：范围选股出现合格候选后由程序主动询问；只有用户明确同意，才重新下载远端数据并运行 T+1、T+2、T+3 模型。单股买入结论不进入预测。

用户只需使用自然语言。程序不会要求选择“尾盘分析”“涨停回马枪”“技术分析”等内部模式，也不会要求传递工具名、结构化参数或分析编号。

程序不连接证券账户、不提交委托、不自动交易。所有分数与结果仅用于公开数据研究排序。

完整业务口径见 [程序介绍](./程序介绍.md)，维护边界见 [项目设计与实现](./项目设计与实现.md)。

## 快速开始

运行环境：Windows、PowerShell 7（`pwsh`）、Python 3.11 或更高版本。

```powershell
cd C:\Users\user\PycharmProjects\gupiaoyanjiu
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -e .
Copy-Item .\agent\.env.example .\agent\.env
```

在 `agent\.env` 中配置一个模型 Provider，并配置 `TUSHARE_TOKEN`。例如：

```dotenv
LANGCHAIN_PROVIDER=deepseek
LANGCHAIN_MODEL_NAME=deepseek-chat
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
TUSHARE_TOKEN=你的Token
```

也可以使用 OpenAI API，或执行 `gpyj openai-login` 使用 ChatGPT/Codex 登录。

## 自然语言使用

进入连续对话：

```powershell
gpyj
```

单轮分析：

```powershell
gpyj run -p "帮我选股票"
gpyj run -p "从半导体行业里选股票"
gpyj run -p "从 AI 算力板块里选"
gpyj run -p "分析深科技"
```

在连续对话中可以继续说：

```text
继续预测首选
预测刚才的第二只备选
```

程序会先用自然语言给出量化结论、关键依据和主要风险，再说明预测需要重新下载数据和训练模型。连续对话会在完整答案显示后弹出编号窗口，最多提供四个预设项，包括首选、靠前备选和“暂不预测”；还可以直接输入其他合格备选的名称或代码。即使最初的问题写了“分析完直接预测”或“不用再问”，这类预先授权也不代替本次选择。用户的选择会作为新的对话回合继续执行，不会再做第三次确认。程序从进程内会话状态取得对应候选，无需复制任何内部编号。直接面向用户的旧 `gupiao`、`yuce` 子命令已经移除，避免自然语言入口与内部工具形成双轨。

指定范围不会由提示词里的静态行业枚举或 `if/else` 猜测。程序先实时读取数据源当前的行业和概念目录，再对候选名称、类别和官方详情页进行核验；唯一且已核验的精确候选可直接采用，多个真实候选仍无法从上下文判断时才澄清一次。用户只会看到普通中文选项，不需要理解数据源分类代码。

如果用户点名一只股票，程序进入单股量化路径，不把它误当成板块，也不会悄悄改成全市场选股。程序先核验该股身份和完整日线，再从当前横截面建立“同行优先、市场参照补足”的有界比较池；随后直接复用范围选股已有的八组日 K 因子、基本面评分、涨停回马枪、尾盘证据、风险扣分、综合评分及推荐门槛，最终明确输出“建议买入”或“暂不建议买入”。结尾会再用一段普通中文收束：先承认真实亮点，再说明为什么当前值得或不值得买，并列出哪些量化条件改善后可以重新评估。单股结论仍不产生预测资格。展示层会核对回答是否包含最终结论、综合分、证据完整度、八组因子分、5/10/20 日动量、组件分、全部未通过条件及这段收束总结，以及价格均线、MACD 正反证、波动回撤、基本面失败原因、成交额日期口径和日线覆盖质量；关键理由缺失或时间口径混淆时，改用结构化结果生成可逐项复核的中文结论。

## 分析会自动做什么

一次分析依次完成：

- 点名单股时建立有界实时比较池，并使用与范围选股相同的量化评分和推荐门槛给出买入结论；

- 确定全市场或日常语言范围；指定范围会先动态发现数据源目录并二次核验；
- 过滤 ST、退市风险、新股、停牌、无效价量、一字涨停、低流动性、历史不足和时点不一致股票；
- 批量计算趋势结构、动量与反转、K 线压力、价量确认、突破与回撤质量、相对强弱、风险与流动性、市场背景八组日 K 因子；
- 加入基本面、估值、同行与行业证据；
- 运行涨停回马枪状态机；
- 14:30 后自动加入尾盘实时证据，14:45 后只对少量靠前候选读取 5 分钟数据；
- 对少量候选做深度财务和技术复核，其中包括指数平滑异同移动平均线的零轴、交叉、动能与背离结构；
- 扣除独立风险分，返回首选、最多四只备选，或明确不推荐。

综合排名分只表示候选间的研究排序，不是上涨概率。缺失证据会从有效权重中移除，同时降低可信度，不会被当成条件失败。

## 指数平滑异同移动平均线结构证据

日线统一特征入口除快线、慢线和柱体外，还一次生成标准化慢线、快慢线间距、两线变化速度和零轴相对距离。结构检测模块只消费这些已整理特征，不访问数据源，也不重复下载行情：

- 零轴背景区分快慢线均在上方、均在下方和分处两侧；
- 交叉严格按相邻交易日的真实穿越记录金叉或死叉，同时给出发生日、零轴区域、标准化强度、距今交易日、新鲜度和失效状态；长期正柱或负柱不会冒充刚发生的交叉；
- 柱体动能区分正向增强、正向衰减、下跌动能减弱和下跌动能增强；
- 顶部与底部背离分别对快线和柱体计算。价格与指标拐点默认使用左二、右二交易日确认，信号日期取右侧确认完成日，不回填到拐点日；同时要求最小拐点间隔、价格变化和指标变化，并记录有效期、失效原因与证据可靠性；
- 价格和指标距离均按收盘价标准化，因此股票价格同比例缩放时结构结论保持一致。

结构结果明确区分分析成功、信息不足、数据不可用和程序错误。第一阶段只把它作为可追溯的解释证据：新增字段不进入八组因子、综合排名或预测模型，顶部背离只提示风险而不扣分，底部背离只表示下跌动能减弱，任何单一交叉或背离都不能产生推荐。智能体必须再结合市场、当前范围、相对强弱、价量和交易风险解释证据冲突。参数集中在 `fenxi.macd_structure`，在完成按确认日的历史表现验证前不启用结构子分。

研究侧另有 `macd_huifang.py` 接收调用方准备好的内存历史面板。它按实际确认日列出事件，统一在次一市场交易日开盘尝试执行，逐笔处理停牌、封涨跌停、整手、滚动成交额、成交参与率、动态滑点和交易成本，并按大盘状态、行业强弱、相对强弱、价量状态、股票范围、时间子区间及附近参数输出结果。基线必须来自不使用结构字段的 `baseline_selected` 历史时点标记；缺少该字段、经时点核验的行业成员或其他关键上下文时，结果会明确降级，不能据此改分。回放参数集中在 `fenxi.macd_structure_validation`。当前只是具备可复核回放能力，尚未取得满足全部覆盖门槛的真实历史结论，生产评分继续保持不变。

## 尾盘结果时点

- 14:30 前：不使用尾盘证据；
- 14:30–14:44：尾盘初筛；
- 14:45–15:00：盘中暂定，加入分钟走势、最高价时间和 VWAP；
- 15:00–15:05：等待完整收盘确认；
- 15:05 后：仅在数据源已提供完整日线时做收盘复核。

交易日身份优先由 Tushare 交易日历确认；遇到限频或暂时不可用时，使用新浪交易所日历远端备用源。所有权威日历均不可用时程序停止时点判断，不用系统星期数冒充法定交易日。

## 数据和性能

- 股票资料、日线、估值、宽基指数和同行样本均在当前操作中访问远端数据源，不读取或写入本地市场数据缓存；
- 指定范围实时读取东方财富行业、概念目录与当前成分，并用官方详情页核验关键范围事实；
- 分析日线以腾讯当前前复权接口为主，使用同一响应中的证券快照核验代码、最新收盘价、成交量和精确成交额；东方财富与 Tushare 只做受控备用，不以旧本地数据兜底；
- 国内公开数据连接可配置为明确直连或继承 Windows 系统代理；直连模式不会意外使用环境或系统代理；
- 一次分析最多读取一次全市场实时快照；
- 单股量化最多读取一次全市场实时快照；当前横截面、比较池日线、指数背景和基本面响应只在本次请求内复用，不写入本地市场缓存；
- 分钟数据只读取排名靠前的少量候选；
- 范围选股完成且存在合格候选时，程序只询问是否预测，不自动训练；单股买入结论不进入预测；
- 连续对话使用结构化编号窗口收集这次确认；只有范围确实含糊或范围选股后存在合格候选时才显示，不把内部专业模式交给用户选择；
- 用户明确确认预测后，才重新下载目标股票、同行、历史估值和宽基指数数据，并补齐模型长窗口；
- 同一次业务调用的交易日历、横截面、板块成分、实时快照和日线响应由请求上下文临时复用，调用结束即释放；
- 数据源失败、时点不一致或字段缺失会进入结果，不会伪装成完整分析。

本地只保留运行所必需的不同类别信息：根目录配置、用户自行配置的凭据、可选对话文本与最小的“需要重新分析”标记，以及默认仅含状态和耗时等元数据的运行记录。运行记录默认保留不超过 14 天、100 次和 100 MB，可在连续对话中用 `/clear-runs` 清除。行情、板块目录、成分、因子、预测输入和模型训练样本都不落盘；分析与预测之间仅有最多 32 条的进程内会话交接，进程重启后必须重新下载并分析。

## 预测口径

预测模型、标签和期限没有改变：

- 预测不能由分析自动触发，必须在分析结果展示后的后续用户消息中得到明确确认；
- 初始请求中的“直接预测”“不用再问”等预先授权不算确认，分析结果后仍会询问一次；后续简单肯定回复默认选择首选，且不再重复确认；
- 每次预测现取远端数据并训练，不复用本地行情、因子或同业样本；
- T 为最近一个已确认完整收盘日；
- 一次预测固定返回 T+1、T+2、T+3；
- 目标日期使用真实交易日历；
- 概率、参考收盘价、区间、验证状态和可信度均来自既有模型；
- 分析排名分不会被换算成预测概率。

## 研究边界

- 公开行情、财务和板块数据可能延迟、限频或缺字段；
- 日 K 与 5 分钟数据不能替代盘口深度、公告核验和人工判断；
- 盘中确认始终是暂定状态；
- 排名、预测和参考价格都不构成收益承诺、目标价或交易指令；
- 交易决定、价格与仓位始终由用户自行判断。
