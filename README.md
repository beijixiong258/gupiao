# A 股分析诊断与规则选股

这是一个供个人使用的中国大陆 A 股研究程序，提供两项功能：点名股票时，整理本次能够取得和计算的完整证据；提出选股要求时，在指定范围内按公开的上涨条件筛选研究候选。

程序不再计算人为综合评分、组件权重或置信度分，不强制把单股诊断归为买入或不买入。三交易日预测、模型训练和预测确认流程已移除。分析完成后直接交付结果。

用户只需使用自然语言，不需要选择“尾盘分析”“涨停回马枪”等内部模式，也不用传递工具名、参数或分析编号。程序不连接证券账户、不提交委托、不自动交易。

完整业务口径见 [程序介绍](./程序介绍.md)，指标公式与限制见 [量化指标说明](./量化指标说明.md)，维护边界见 [项目设计与实现](./项目设计与实现.md)。

## 快速开始

运行环境：Windows、PowerShell 7（`pwsh`）、Python 3.11 或更高版本。

```powershell
cd C:\Users\user\PycharmProjects\gupiaoyanjiu
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -e .
Copy-Item .\agent\.env.example .\agent\.env
```

在 `agent\.env` 中配置一个模型 Provider，并配置 `TUSHARE_TOKEN`。例如：

```dotenv
LANGCHAIN_PROVIDER=deepseek
LANGCHAIN_MODEL_NAME=deepseek-chat
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
TUSHARE_TOKEN=你的Token
```

也可以使用 OpenAI API，或执行 `gpyj openai-login` 使用 ChatGPT/Codex 登录。

指定范围先读取数据源当前的行业和概念目录，再核验候选名称、类别和官方详情。唯一且已核验的精确候选可直接采用；多个真实候选仍无法从上下文判断时，才用普通中文澄清一次。目录不可用或核验冲突会如实说明，不会被当成“没有这个板块”。

## 单股：完整证据报告

“分析深科技”进入独立的单股证据路径。程序先核验股票身份和可用日线，再尽量补充当前行情、财务、宽基指数和有界同行参照；不会把目标股票当成选股候选先筛掉，也不会改成全市场选股。

报告按内容组织，先给出可读摘要，再展示：

- 股票资料、实际日线截止日、历史覆盖范围、最新一根日线与当前行情；
- 趋势结构、动量与反转、K 线压力、价量确认、突破与回撤质量、相对强弱、风险与流动性、市场背景八组原始指标；每项保留当前数值、单位、中文含义和缺失情况；
- 完整技术摘要，包括均线、MACD、RSI、波动和回撤等已计算信息；
- 已取得的基本面与估值字段、比较样本中的估值分位、报告期、公告日和来源；
- 涨停回马枪状态、尾盘证据、七类补充诊断、可交易性限制；
- 支持证据、反证、风险、数据缺口、来源降级及重新评估条件。

原始指标不会汇成一个总分，估值分位和 RSI 等指标自身的数值尺度也不会被解释成上涨概率。报告不只截取前几项财务或指标证据；模型遗漏的内容由共享展示层按结构化事实补齐，不重新计算数字。

同行、指数、财务、实时或分钟数据不可用时，保留其他可分析内容并标明“部分证据缺失”。某项窗口不足只让该指标不可用，不额外设置单股最低历史长度或最低同行数量的整体门槛。目标身份、交易日期或目标日线无法支持分析时，才返回相应不可用原因；程序错误单独报告。

## 范围：按条件筛选研究候选

范围选股先进行代码、风险警示、上市时长、停牌、有效价量、一字涨停、流动性和日线质量等基础检查，再逐项核验以下条件：

| 条件 | 程序核验方式 |
|---|---|
| 趋势方向 | 收盘价高于 MA20，且 MA5 高于 MA20 |
| 动量方向 | 5 日收益、20 日收益和 MACD 柱均大于零 |
| 相对表现 | 20 日收益高于同期沪深 300 收益 |
| 量能确认 | 5 日平均成交量 / 20 日平均成交量不低于 1 |
| 波动限制 | 20 日年化波动不高于已有配置上限 |
| 深度复核 | 技术证据可用，且当前适用的可交易性与实时核验通过 |

必需字段缺失不能算通过。候选会公开每条条件的实际值、通过状态、未满足项和缺失原因。

满足条件的候选按五个原始维度进行 Pareto 非支配分层：20 日相对沪深 300 超额收益、5 日收益、20 日收益、较低的 20 日波动、完整日线真实成交额。若 A 在全部维度不差于 B，并且至少一项更好，A 才支配 B；互有长短的股票可以处于同一层。同层仅按成交额和代码稳定展示，不表示谁更可能上涨。

范围选股有流动性抽样、日线取得和深度复核数量上限。结果公开输入范围、各阶段数量、抽样限制和比较口径，只比较本次取得并完成复核的样本，不宣称已找到全市场最可能上涨的股票。默认最多展示一个排在前面的研究候选和四个后续候选；不足时不凑数。深度复核后没有合格候选时，最多保留一个注明“未通过选股条件”的观察对象，展示其证据与原因；早期没有可分析对象时不会制造观察对象。

## 结构与补充诊断

MACD 结构识别零轴背景、真实交叉、柱体动能以及快线和柱体的顶底背离。交叉记录发生日、新鲜度和失效状态；背离拐点默认左二、右二交易日确认，信号日期取右侧确认完成日，不回填到拐点日。距离按价格尺度标准化，参数集中在 `fenxi.macd_structure`。这些结构与市场、相对强弱、价量和风险一起解释，不单独产生买卖结论。

七类补充诊断是下行风险、均线偏离 ATR 倍数、20 日价量压力、流动性稳定性、营收与利润增长、盈利与现金流核对、财报时点与来源。单股和范围深度复核共用已有数据计算，缺失与零值分开显示。CMF 只描述收盘位置和成交量的压力，不是实际主力资金净流入。

研究侧保留独立的 `macd_huifang.py`，只接收调用方提供的内存历史面板。它按实际确认日回放，处理次一交易日执行、停牌、封板、整手、成交参与率、滑点和成本，并披露基线与历史时点覆盖限制。它不训练或发布预测，也不自动修改生产筛选规则；具备回放能力不等于已经取得可靠的真实历史增益结论。

## 尾盘结果时点

- 14:30 前：不使用尾盘证据；
- 14:30–14:44：尾盘初筛；
- 14:45–15:00：盘中暂定，加入分钟走势、最高价时间和 VWAP；
- 15:00–15:05：等待完整收盘确认；
- 15:05 后：仅在数据源已提供完整日线时做收盘复核。

日线截止日、报告生成时间和实时核验状态分别披露。动态均线和盘中成交额不会冒充完整收盘指标。缺少分钟数据时保留已有证据及缺失原因。

交易日身份优先由 Tushare 交易日历确认；缺少 Token、客户端初始化失败、限频或暂时不可用时，尝试新浪交易所日历。日历必须覆盖所需历史窗口，不能静默截短行情。所有权威日历均不可用时停止依赖交易日身份的判断，不用系统星期数冒充法定交易日。

## 数据和性能

- 股票资料、日线、估值、宽基指数和同行样本均从本次远端请求取得，不读取或写入本地市场数据缓存；
- 指定范围使用东方财富当前行业、概念目录与成分，并核验关键范围事实；
- 分析日线以腾讯当前前复权接口为主，使用同一响应的证券快照核验代码、最新收盘价、成交量和精确成交额；东方财富与 Tushare 为受控备用；
- 国内公开数据默认直连，也可明确配置继承 Windows 系统代理；直连模式不继承环境或系统代理；
- 一次分析最多取得一次全市场实时快照，交易日历、横截面、成分、日线和基本面仅在本次请求内复用；
- 单股使用有界比较池，范围使用受限抽样与批量行情；分钟和深度财务、技术复核限于少量候选；
- 数据源失败、时点不一致和字段缺失进入结构化结果，外层不会把不可用或程序错误包装成完整分析。

单股与范围共用行情质量和可交易性计算。范围将当前硬性限制用于过滤，单股将这些限制作为报告中的证据保留。范围详情核验部分失败时，保留尚未确认的候选，不把失败当作排除证据；日线主源非空但不合格时，在既有限额内尝试备用源，各源遵循相同的对应请求质量要求。

本地只保留根目录配置、用户配置的凭据、可选对话文本与“需要重新分析”标记，以及默认仅含状态和耗时等元数据的运行记录。运行记录默认不超过 14 天、100 次和 100 MB，可在连续对话中用 `/clear-runs` 清除。行情、目录、成分和因子不落盘；进程重启后需要重新取得数据并分析。

## MCP

`gpyj-mcp` 可供自然语言智能体集成：

```powershell
gpyj-mcp
gpyj-mcp --transport http --host 127.0.0.1 --port 8765
```

MCP 与连续对话共用同一分析工具，支持点名单股、指定范围和明确要求的选股数量。参数和分析编号属于内部协议，不是最终用户需要操作的内容。

## 研究边界

公开数据可能延迟、限频或缺字段；日 K 与 5 分钟数据不能替代盘口深度、公告核验和人工判断。盘中确认始终暂定；当前行业标签不能完整还原历史成分。条件通过和非支配层次都不构成收益承诺、目标价或交易指令，交易决定、价格与仓位由用户自行判断。
