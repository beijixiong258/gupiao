# A 股分析诊断与规则选股

这是一个供个人使用的中国大陆 A 股研究程序，提供两项功能。选股的明确目标是选出截至提问时、在用户给定范围和要求中最优秀的个股，并说明优选依据；单股分析围绕用户的猜想，使用严谨且可解释的量化证据检验支持、反证与缺口，形成综合判断。

用户未提出风险要求时，选股不默认追求低风险或低波动，也不主动追加风险偏好问题或过滤条件；用户明确提出后再纳入相应限制。每次判断使用当时可取得并核验的数据，公开实际截止时间与比较覆盖范围。

**当前优选口径：** 范围候选分批全量请求，以用户确认的“推荐指数（当前量价状态）”排序。指数合成20日收益、带方向路径效率与上涨成交额占优度，公开原值、共同有效样本中的分位和组分。完成比较和技术复核后统一重算，再裁剪展示数量；按未舍入指数降序，完全相同明确并列，代码只稳定显示。ST、上市时长、成交额大小、波动上限和全部看涨等条件仅在用户明确提出时采用；数据有效性与适用的成交核验仍保留。

推荐指数的固定公式与权重是公开的产品选择，不训练模型，不把指数当成收益率、上涨概率或置信度，不增加风险扣分或推荐分数门槛。旧20／5日非支配排序保留为研究对照。单股诊断不强制归为买入或不买入；三交易日预测、模型训练和预测确认流程不恢复。分析完成后直接交付结果。

用户只需使用自然语言，不需要选择“尾盘分析”“涨停回马枪”等内部模式，也不用传递工具名、参数或分析编号。程序不连接证券账户、不提交委托、不自动交易。

整个程序只面向沪深京A股。B股、基金、债券、指数以及港美股不进入单股目标或选股候选；指数仅用于独立的市场比较。个股必须经本次真实股票目录核验身份，不能只凭六位数字认定为A股。

完整业务口径见 [程序介绍](./程序介绍.md)，指标公式与限制见 [量化指标说明](./量化指标说明.md)，维护边界见 [项目设计与实现](./项目设计与实现.md)。

## 当前权限与持仓分析

默认财务链路使用东方财富公开财务主表，核验证券代码、报告期和公告日，不请求当前账号无权限的 `fina_indicator`。Tushare 股票目录和日终估值受限时，分别使用本次公开股票目录及带明确日期的逐日估值；日历保留权威备用。恢复后的有效证据正常使用，主源失败保留在来源记录中。未知或实际仍不可用的字段继续标明缺失，不能把接口配置完成当成权限验证成功。

单股与最终选股候选新增“持仓分析（通达信控盘指标）”：保留最多30条来源观测，提供连续1／5／20个交易间隔的原值变化、本次样本区间位置，以及同日股价、成交量和成交额对照。只在最终完整报告阶段补充控盘，不加入推荐指数、不改变用户条件和候选数量。初筛证据不足但无明确不合格反证的对象继续技术复核，用户提出的研究观点也逐股核验。

控盘取数提取自 eltdx 的请求和多表解析协议，沿用本项目网络层，不安装整包。算法、分母、百分比单位和真实更新频率尚未核实，因此显示原值点，`realtime_verified=false`；不输出机构／个人互补比例，不把上升或下降直接解释成增减仓。来源可用与实际持仓解释完整分开，报告如实保留 `partial`。所有市场资料仍只在同一次请求内存复用。

```powershell

.\venv\Scripts\Activate.ps1
python -m pip install -e .
Copy-Item .\agent\.env.example .\agent\.env
```

自然语言请求先经过独立的意图识别，再进入受约束的工具执行与结果解释。识别节点每轮单独调用一次模型，只开放内部意图记录工具，不读取行情；根据完整对话区分单股分析、范围选股、结果追问、使用咨询、必要澄清和不支持的请求，并保留股票或范围原话、显式条件、研究问题、缺失信息及是否需要新市场数据。

执行阶段只开放该类意图允许的工具，调用前核对单股对象与命名范围，防止把点名单股或指定范围误转成全市场。识别失败就停止，不默认选股；需要分析或澄清时，不能只生成一段文字就声称完成。结果追问、使用咨询和不支持的请求不开放业务工具；需要重新取数的追问应识别为新的分析请求。显式条件在本轮系统上下文及压缩后保留，完整意图结果仅留在内存，运行记录只保存意图阶段的状态、耗时等元数据。

未限定范围的选股默认全市场A股，不因用户未指定行业而追问范围；只有上下文不能唯一确定“这个板块”等真实含糊指代时才澄清。未明确数量或只说“一些”“几只”时保留未指定，不擅自改成一只，沿用既有默认展示数量；明确数量才传入1至5的整数。

“整个沪深主板”是独立的上市市场范围，不需要再指定行业或概念。程序优先采用本次已核验的 Tushare 股票目录上市市场分类；分类缺失或质量不合格时，才尝试已有东方财富明确主板类别的成员完整分页。公开估值的市场类别包含跨上市板的特殊分类，原值可以保留，但不能用沪深A股类别减去创业板、科创板类别推断主板身份。备用名单仍核对本次A股身份、代码、名称和适用日期，保留来源、取得时间、失败与降级原因、未匹配记录和实际覆盖；主源已明确的非主板身份不能被备用覆盖，不能凭代码前缀构造身份，也不扩大到创业板、科创板或北交所。普通行业、概念等命名范围才读取当前目录，再核验候选名称、类别和官方详情。唯一且已核验的精确候选可直接采用；多个真实候选仍无法从上下文判断时，才用普通中文澄清一次。目录不可用或核验冲突会如实说明，不会被当成“没有这个板块”。

泛称匹配得到多个已核验候选时，智能体先结合原话审查语义，再决定采用范围或澄清。采用时保留实际范围与解释，不改变用户指定的数量和市值条件。

## 单股：完整证据报告

“分析深科技”进入独立的单股证据路径。程序先核验股票身份和可用日线，再尽量补充当前行情、财务、宽基指数和有界同行参照；不会把目标股票当成选股候选先筛掉，也不会改成全市场选股。

报告按内容组织，先给出可读摘要，再展示：

- 股票资料、实际日线截止日、历史覆盖范围、最新一根日线与当前行情；
- 趋势结构、动量与反转、K 线压力、价量确认、突破与回撤质量、相对强弱、风险与流动性、市场背景八组原始指标；每项保留当前数值、单位、中文含义和缺失情况；
- 完整技术摘要，包括均线、MACD、RSI、波动和回撤等已计算信息；
- 已取得的基本面与估值字段、比较样本中的估值分位、报告期、公告日和来源；
- 涨停回马枪状态、尾盘证据、七类补充诊断、可交易性限制；
- 支持证据、反证、风险、数据缺口、来源降级及重新评估条件。

原始指标不会汇成一个总分，估值分位和 RSI 等指标自身的数值尺度也不会被解释成上涨概率。报告不只截取前几项财务或指标证据；模型遗漏的内容由共享展示层按结构化事实补齐，不重新计算数字。

数据覆盖率与真实指标值分开呈现，覆盖率为零不表示指标为零。形态突破期限始终从基准涨停日计数，缩量不重置期限；缺少有效估值比较样本时只报告原始数值与限制，不断言估值高低。

指标注册表公开公式、窗口、最低样本数和缺失规则。缺失历史不填成中性值，缺失成交额不以价格乘成交量替代；单股与范围复用计算口径。范围深度复核核对身份、日期及未舍入指标，失效历史形态不进入当前风险摘要。

报告中的滚动统计注明实际有效样本数。相同指标定义只向模型传递一次，完整报告仍逐项展开；对话压缩保留本轮真实分析状态，避免完成后重复选范围。

自然语言解释逐项绑定注册表中的对象、名称、窗口和单位：市场参照子池均值不能改称沪深300收益，超额收益不能改称指数本身收益，14日ATR不能随相邻20日波动指标改写窗口。没有单独返回的指数收益只保留已给出的超额证据，不补猜数值。

“现有证据详解”按价格与趋势、价格位置与突破、动能、量价、相对表现、市场背景、下行风险、形态、财务和盘中状态展开本次已计算事实，并列明缺口、影响与补齐条件。20日收益与MA20只构成趋势判断的底稿；出现分歧时说明具体冲突，不以一句“证据有分歧”代替解释。模型正文不再固定压缩至300–600字，重要判断需说明数值、窗口、含义及反证；完整原始指标仍由共享展示层保留。均量比不能代替逐日放量核验，越过历史高点不能直接称为持续突破，过期信号仅作为历史观察。

同行、指数、财务、实时或分钟数据不可用时，保留其他可分析内容并标明“部分证据缺失”。某项窗口不足只让该指标不可用，不额外设置单股最低历史长度或最低同行数量的整体门槛。目标身份、交易日期或目标日线无法支持分析时，才返回相应不可用原因；程序错误单独报告。

## 范围选股：当前筛选与比较实现

“小盘股”需要明确总市值或流通市值，以及具体上限；例如“推荐3只流通市值低于100亿元的股票”。例子中的100亿元不是默认阈值。口径或上限不明确时先澄清，本轮不取候选、不输出此前的全市场候选；当前不支持按市值百分位筛选。智能体必须显式传入市值条件，不能把“小盘股”当作无市值限制的全市场请求。

市值条件在基础价量检查之后、分批历史行情下载之前执行。“低于”不含上限，“不超过”包含上限。优先用本次请求取得的 `tushare_daily_basic` 日终市值，受限时采用 `eastmoney_daily_valuation` 明确逐日估值，逐股核验代码、分析日、有限正数和重复数据冲突；万元转换为元，分别保留总市值和流通市值口径。该接口在同次请求内复用，包括失败，不新增本地缓存。市值未核验者不进入候选，报告单列证据不足数量；接口限频或缺失不能解释为股票超过上限，也不使用盘中快照补猜。结果披露条件、通过数、未核验数，以及每只返回候选的原值、日期和来源取得时间。

范围默认核验股票身份、有效价量、完整分析日及连续比较窗口。推荐指数需要21条连续有效价格及后20日真实成交额，路径变化与总成交额分母均须大于零；上市时间短本身不排除。逐项状态为 `met / unmet / unavailable`，缺失不算通过。用户明确提出的趋势、收益、波动、ST排除、上市时长或成交额限制，经 `tiaojian` 记录实际指标、边界和来源后执行；未指定时不追加，也不询问风险偏好。原有5000万元流动性观察基准不再默认阻断候选。

通过条件且三个原始量均有效的股票组成同日共同比较池（N≥2）。20日收益R、带方向路径效率E与上涨成交额占优度U各自使用平均升序名次分位 `p=(rank-0.5)/N`；价格组 `P=(pR+pE)/2`，量价组 `V=pU`，推荐指数 `I=100×sqrt(P×V)`。价格组与量价组几何等权，价格组内两项等权；不因缺失重配权重。旧20／5日Pareto分层仅作研究对照。指数高表示当前相对量价状态更符合本规则，不表示未来收益最高；同日同基准20日超额不重复加入，波动、均线、MACD、形态、行业、财务和控盘不额外加分。

`history_batch_size` 只限制每批取数规模，不截断范围。逐股先算完整时间窗口，再合并末日截面，避免构造全市场历史宽表。对潜在合格者完成本地技术核验、重新比较后，才为最终候选补财务、分钟及完整报告。`deep_analysis_limit` 和 `minute_candidate_limit` 仍限制昂贵补充请求，用户要求一只时只生成一份候选完整报告。展示数量不改写技术复核数和全部已确认合格数；程序错误停止并保留原因。

本次“最优”是上述公开技术表现规则下的优选，不冒称已知未来收益最优或公司内在价值最优。范围整体下跌仍可比较相对最好者，并明示其绝对表现；用户要求上涨时才增加相应条件。报告公开 `comparison_coverage`、来源失败、实际比较和复核数量，未取得的候选不能算作已经比较。默认最多展示一只在前候选及四只后续候选；无合格者最多保留一只明确标为未通过条件的观察对象。

用户有明确单股观点时，`yanjiu_wenti` 保存原始问题、可观测命题和不能核验的部分；`research_question` 给出逐项原值、支持/部分支持/直接反证/证据不足及复评条件。不能拿任意代理指标代替整个观点，更不能把指标核验转为未来概率；普通“分析某股”直接给综合分析。正ROE或正利润同比仅是财务背景，不机械加入看涨证据。同行优先真实行业一致且同日已核验总市值相近者，缺规模时披露补位与样本局限。正文先给结论，完整证据从共享结构一次展开。

选股中的未来目标同样保留原文和不能核验的部分，例如“持有一周收益最大”不能改写成过去5日收益条件或推荐指数。指数仅描述当前状态；未核验目标使报告保留 `partial / information_partial`，但不改变已取得候选的 `selection_outcome`，不训练模型或声称未来目标已满足。固定公式的数学排序检查与历史向前收益检验分别报告，历史有效性不足不能包装成已验证的上涨能力。

已核验盘中快照单独解释今日变化及是否削弱原日线依据；实时与历史价格口径未对齐时不比较均线位置，盘中暂定变化不改写完整日线排序。

顶层 `status/outcome` 表示报告完成情况，`selection_outcome` 单独表示是否已有合格候选。必需比较指标、实时行情或基础价量证据不足时保留 `partial / information_partial`，说明尚无法完整确认是否合格；补充财务或分钟证据缺失时，已通过必需条件的候选仍可展示并披露缺口。明确未满足条件与来源不可用分别记录，工具和对话层继承部分完成状态。

## 结构与补充诊断

MACD 结构识别零轴背景、真实交叉、柱体动能以及快线和柱体的顶底背离。交叉记录发生日、新鲜度和失效状态；背离拐点默认左二、右二交易日确认，信号日期取右侧确认完成日，不回填到拐点日。距离按价格尺度标准化，参数集中在 `fenxi.macd_structure`。这些结构与市场、相对强弱、价量和风险一起解释，不单独产生买卖结论。

七类补充诊断是下行风险、均线偏离 ATR 倍数、20 日价量压力、流动性稳定性、营收与利润增长、盈利与现金流核对、财报时点与来源。单股和范围深度复核共用已有数据计算，缺失与零值分开显示。CMF 只描述收盘位置和成交量的压力，不是实际主力资金净流入。

研究侧保留独立的 `macd_huifang.py`，只接收调用方提供的内存历史面板。它按实际确认日回放，处理次一交易日执行、停牌、封板、整手、成交参与率、滑点和成本，并披露基线与历史时点覆盖限制。它不训练或发布预测，也不自动修改生产筛选规则；具备回放能力不等于已经取得可靠的真实历史增益结论。

## 尾盘结果时点

- 14:30 前：不使用尾盘证据；
- 14:30–14:44：尾盘初筛；
- 14:45–15:00：盘中暂定，加入分钟走势、最高价时间和 VWAP；
- 15:00–15:05：等待完整收盘确认；
- 15:05 后：仅在数据源已提供完整日线时做收盘复核。

日线截止日、报告生成时间和实时核验状态分别披露。动态均线和盘中成交额不会冒充完整收盘指标。缺少分钟数据时保留已有证据及缺失原因。

当前快照除来源日期核验外，采用 120 秒有效交易时段延迟上限；09:25–09:30、11:30–13:00 与收盘后不积累延迟，午休前已过期的报价不会恢复有效。实际墙上延迟仍单独显示。15:00 后不能用收盘前报价确认收盘；09:25 撮合前不能确认当前成交，当前可交易性还要求有效正成交量和成交额，但盘中金额不套用全天流动性门槛。120 秒是本程序的保守工程核验口径，不是交易所规定、行情服务承诺或成交保证；非实时历史日线不强制当前时效。

休市、盘前和盘后的历史基础条件检查不表示当前可交易；程序分别展示历史快照与当前行情是否经过核验。指数主源失败但备用源已通过质量检查时保留来源降级记录，已恢复的数据不再列为缺口。

交易日身份优先由 Tushare 交易日历确认；缺少 Token、客户端初始化失败、限频或暂时不可用时，尝试新浪交易所日历。日历必须覆盖所需历史窗口，不能静默截短行情。所有权威日历均不可用时停止依赖交易日身份的判断，不用系统星期数冒充法定交易日。

## 数据和性能

- 股票资料、日线、估值、宽基指数和同行样本均从本次远端请求取得，不读取或写入本地市场数据缓存；
- 命名范围使用东方财富当前行业、概念目录与成分；整个沪深主板优先使用本次已核验股票目录的上市市场分类，质量不足才使用现有公开主板成员名单备用，两者分别核验关键范围事实；
- 分析日线以腾讯当前前复权接口为主，使用同一响应的证券快照核验代码、最新收盘价、成交量和精确成交额；东方财富与 Tushare 为受控备用；
- 国内公开数据默认直连，也可明确配置继承 Windows 系统代理；直连模式不继承环境或系统代理；
- 一次分析最多取得一次全市场实时快照，交易日历、横截面、成分、日线和基本面仅在本次请求内复用；
- 单股使用有界比较池，范围分批全量请求并只合并最新因子截面；潜在合格者完成技术复核后，分钟和深度财务请求限于最终展示候选；
- 范围技术摘要就地复用同次因子构造的完整特征，复核继续检查身份、日期和未舍入原值；只保留摘要，不另存全市场历史特征宽表。MACD 拐点批量计算保持相同窗口、容差、确认日和缺失规则；
- 数据源失败、时点不一致和字段缺失进入结构化结果，外层不会把不可用或程序错误包装成完整分析。

特征、技术摘要及因子增强的意外计算异常立即终止本轮，统一返回 `error / program_error`，不跳过出错股票后继续发布候选；来源层已明确返回的缺失、不可用及短历史仍按原有证据状态处理。

单股与范围共用行情质量和可交易性计算。范围将当前硬性限制用于过滤，单股将这些限制作为报告中的证据保留。范围详情核验部分失败时，保留尚未确认的候选，不把失败当作排除证据；日线主源非空但不合格时，在既有限额内尝试备用源，各源遵循相同的对应请求质量要求。

个股整段历史的交易日覆盖率仅用于披露，不作为默认硬过滤；旧配置 `minimum_history_session_coverage` 不再生效。各源核验必要样本及最新完整交易日后，按权威日历补入缺失行。范围在选源阶段就要求末21个交易日有连续有效收盘价，必要窗口缺失时按既有限额尝试备用源；单股只要求目标日价格可用，短历史或较早缺口只影响相应指标窗口，不阻断其余证据。最新日线的开、高、低、收价格须齐全有效。日线来源的无效或重复日期拒绝采用，不任意保留一条；历史价量缺失保留在原日期，不能删行后拼接计算。

宽基指数复用本次权威交易日历：核验截止日及末 21 个交易日的连续有效收盘价，主源缺日、重复日期或价格无效时尝试已有备用源，整段采用合格来源，不拼接价格。更早历史按交易日历保留缺口，受缺口影响的收益窗口留空；短个股历史可以独立取得足够的指数窗口，不增加单股历史门槛。逐源质量、缺失日期与降级原因保留在结果中。

横截面的换手率和流通市值只有在逐行确认日终来源、行情日、估值日与目标日线日一致后才能填补日线指标；当前明确支持的日终补充来源是 `tushare_daily_basic` 和 `eastmoney_daily_valuation`；公开备用的日终收盘价还需与同日原始日线交叉核验。已有有效历史值保留，缺失补充值不覆盖。实时或时点未核验字段保留在独立原始资料中，不注入上一完整交易日。

本地只保留程序配置、用户配置的凭据、可选对话文本与“需要重新分析”标记，以及默认仅含状态和耗时等元数据的运行记录。运行记录默认不超过 14 天、100 次和 100 MB，可在连续对话中用 `/clear-runs` 清除。行情、目录、成分和因子不落盘；进程重启后需要重新取得数据并分析。

运行记录裁剪、`/clear-runs` 和临时运行目录回收统一移动到当前用户的 `Desktop/智能体回收站/垃圾桶`，不永久删除，不覆盖同名记录。目标必须位于指定工作目录内，目录链接和垃圾桶本身不可作为清理目标；自动裁剪或临时目录移动失败时保留原目录并记录警告，继续交付分析结果；显式清理失败仍报告错误。

ChatGPT OAuth 适配器将应用系统提示映射到 Responses 的 `instructions`，保留用户消息和工具调用往返内容，避免把后端不接受的 `system` 消息放入 `input`。模型预检使用该正式适配器发起最小文本请求，单次超时15秒且不重试；收到有效文本才返回就绪。凭据存在不代表网络、模型权限或推理可用，超时和认证失败均报告为关键失败。其他提供方保留既有检查方式。

## 配置与安装体积

默认量化配置位于 `agent/src/lianghua_peizhi.json`，随 wheel 发布；源码根目录如果存在 `lianghua_peizhi.json`，继续优先采用该显式配置。业务配置和运行记录策略使用同一配置路径，安装后无需依赖原始源码目录。环境变量与 `.env` 由轻量配置模块统一读取，行情模块不会为读取凭据加载模型 SDK。历史研究配置独立校验，仅调用回放时加载研究计算模块。

测试源码与 pytest 开发依赖已移出本项目。发布清单排除测试、虚拟环境、运行记录和字节码，只随包携带明确列出的业务配置。当前运行依赖保留模型、行情和 MCP 功能；不再需要旧预测阶段的 XGBoost、scikit-learn、SciPy。项目 wheel 与包含第三方库的虚拟环境分别统计体积，直接复制整个 `venv` 会带入历史遗留依赖。

## MCP

`gpyj-mcp` 可供自然语言智能体集成：

```powershell
gpyj-mcp
gpyj-mcp --transport http --host 127.0.0.1 --port 8765
```

MCP 与连续对话共用同一分析工具及范围类型，包括整个沪深主板 `main_board`；支持点名单股、指定范围和明确要求的选股数量，数量未指定时可传 `null`。MCP 直接业务调用不经过上述自然语言意图识别节点，仍由业务入口核验身份、范围、条件和数据。参数和分析编号属于内部协议，不是最终用户需要操作的内容。

## 研究边界

公开数据可能延迟、限频或缺字段；日 K 与 5 分钟数据不能替代盘口深度、公告核验和人工判断。盘中确认始终暂定；当前行业标签不能完整还原历史成分。条件通过和推荐指数都不构成收益承诺、目标价或交易指令，交易决定、价格与仓位由用户自行判断。
